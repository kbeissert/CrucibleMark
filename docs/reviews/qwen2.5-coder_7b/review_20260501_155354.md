## Code Quality Audit: Kompetenz mit Lücken

Mit 55.5 Punkten im Code-Quality-Modul landet qwen2.5-coder:7b unterhalb der Erwartungen, die man an ein dezidiertes Coder-Modell stellt. Das ist kein vernichtendes Urteil, aber es bedarf einer ehrlichen Einordnung.

Im untersuchten Sicherheits-Audit (code_quality_002) zeigt das Modell, dass es grundlegende Sicherheitskonzepte kennt und korrekt in Markdown-Tabellen formatiert. Es identifiziert SQL-Injection, Path Traversal, CSRF und mehrere Cookie-Schwächen — das sind die offensichtlichen Treffer, die ein erfahrener Entwickler nach kurzem Überfliegen ebenfalls notieren würde. Doch bei 19 vom Golden Standard identifizierten Schwachstellen bleibt das Modell bei 14 stehen, und die Qualität dieser 14 ist uneinheitlich.

Besonders auffällig ist die Fehlklassifikation der API-Key-Schwachstelle: Das Modell bezeichnet sie als "SQL Injection in API authentication", obwohl es sich um einen Type-Juggling-Fehler beim Loose-Comparison-Operator handelt — `true == "s8sk_api_2024"` evaluiert in PHP zu `true`, ein klassisches und kritisches Sicherheitsproblem, das konzeptuell nichts mit SQL zu tun hat. Diese Verwechslung ist kein Tipp-Fehler, sondern ein Verständnisfehler. Hinzu kommen zwei falsch positive Befunde: Das Modell meldet SQL-Injection im Profil-Update, obwohl dort Prepared Statements korrekt eingesetzt werden, und vermutet Command Injection im File Manager, wo tatsächlich Path Traversal das Problem ist.

Session Fixation, Hardcoded DB-Credentials, Reset-Token ohne Ablaufzeit und Header Injection nach dem Output fehlen vollständig. Die Erklärungen sind flach: Angriffsvektoren werden nicht ausgeführt, Exploit-Ketten nicht skizziert, die fünf impliziten Schwachstellen nur teilweise adressiert.

Dazu kommt ein gravierender Compliance-Fehler: Die Aufgabe verlangt explizit deutsche Ausgabe, das Modell antwortet vollständig auf Englisch. Das ist kein Nuancenproblem — es ist ein direkter Verstoß gegen die primäre Aufgabenbedingung, der einen automatischen Punktabzug auslöst.

Die P95-Antwortzeit dieses Moduls beträgt 207,83 Sekunden, und ein Timeout trat auf. Das ist für ein 7B-Modell ein ungewöhnlich langer Tail, der auf die Grenzen des Modells bei umfangreichen Analyse-Aufgaben hinweist.

## Logisches Reasoning: Strukturell schwach, aber nicht hoffnungslos

Mit 49.83 Punkten im Reasoning-Modul zeigt qwen2.5-coder:7b, dass logische Puzzles außerhalb des Coding-Kontexts eine echte Schwäche darstellen. Im untersuchten Protokoll (reasoning_metacog_003) greift das Modell das klassische Zwei-Wächter-Rätsel auf und formuliert eine Frage, die logisch nicht das leistet, was sie soll.

Die Kernidee des Rätsels — eine Frage zu konstruieren, die durch doppelte Negation bei beiden Wächtern zur selben Antwort führt — wird vom Modell nicht klar artikuliert. Die vorgeschlagene Frage ist nicht äquivalent zur Standardlösung ("Was würde der andere Wächter sagen..."), und das Modell verifiziert seine eigene Antwort nicht. Die Terminologie (TWGP, WL) wird eingeführt, aber nicht konsequent verwendet, was den Gedankengang zusätzlich verschleiert.

Positiv zu vermerken: Das Modell verwendet die angeforderten `<thought>`-Tags, antwortet auf Deutsch und zeigt zumindest den Versuch, mehrere Strategien zu explorieren. Das Reasoning ist nicht leer, aber es ist unvollständig und an der entscheidenden Stelle fehlerhaft. Für ein Coder-Modell dieser Größe ist das ein erwartbares Profil — Logik-Puzzles ohne Code-Bezug gehören nicht zum Kerntraining.

## Datenschutz und Datenhoheit

Dennoch ist die Weights-Provenienz relevant: Das Modell wurde von Alibaba Cloud entwickelt, einem chinesischen Unternehmen, das dem chinesischen National Security Law (NSL), dem Cybersecurity Law (CSL) und dem Data Security Law (DSL) unterliegt. Das berechnete Sovereign Risk ist HIGH. Für Unternehmen, die das Modell lokal betreiben, bedeutet das konkret: Die Weights selbst sind unter chinesischem Recht entstanden, und es lässt sich nicht vollständig ausschließen, dass staatliche Einflussnahme auf das Training stattgefunden hat. Alibaba Cloud stellt ein GDPR DPA bereit, was für den API-Betrieb relevant wäre — beim lokalen Einsatz ist die DSGVO-Frage dagegen auf die Datenverarbeitung auf dem eigenen System beschränkt. Für sicherheitskritische Umgebungen oder Anwendungen, die sensible Daten verarbeiten, ist eine interne Risikoabwägung zur Weights-Provenienz ratsam.

## Fazit

qwen2.5-coder:7b ist ein Modell, das weiß, wo es hingehört — und außerhalb dieses Bereichs spürbar nachlässt. Die CLI-Performance von 85.56 Punkten ist der klarste Beweis für das, wozu das Modell gebaut wurde: schnelle, präzise technische Antworten auf engem Raum. Mit 39.11 Tokens pro Sekunde und einem stabilen Laufverhalten auf Edge-Hardware ist es für Autocomplete, einfache Agenten-Tasks und interaktive DevOps-Workflows eine legitime Wahl.

Die Schwächen sind strukturell, nicht zufällig. Security-Audits mit 55.5 Punkten, Reasoning mit 49.83 Punkten, Cultural Intelligence mit 44.7 Punkten — das sind keine Ausreißer, sondern das erwartbare Profil eines 7B-Coder-Modells, das für Sprachverständnis und kulturelle Feinheiten schlicht nicht optimiert wurde. Dass das Modell im Code-Quality-Audit auf Englisch antwortet, obwohl Deutsch gefordert war, und in content_transformation_004 denselben Fehler wiederholt, ist kein Architekturproblem — es ist ein Instruction-Following-Problem, das im Produktiveinsatz ohne Nachkontrolle direkt fehlschlägt.

Über alle Tests hinweg keine nennenswerten Halluzinationen — das Modell erfindet lieber nichts, als sich zu blamieren. Die Fehlklassifikation der Type-Juggling-Schwachstelle als SQL-Injection ist ein Verständnisfehler, kein halluzinierter Befund.

Wer qwen2.5-coder:7b als lokales Coding-Assistenzsystem einsetzt, bekommt ein schnelles, speicherfreundliches Werkzeug mit echter Stärke im technischen Kernbereich. Wer es für Dokumentation, Sicherheitsanalysen mit hohem Anspruch oder mehrsprachige Content-Aufgaben einplant, sollte entweder ein größeres Modell oder einen menschlichen Review-Schritt einkalkulieren. Die Weights-Provenienz aus dem Alibaba-Ökosystem ist für sicherheitsbewusste Umgebungen eine Abwägungsfrage, keine Ausschlussbedingung — aber sie sollte bewusst getroffen werden.
