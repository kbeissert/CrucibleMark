# CrucibleMark Review: deepseek-v3.2:cloud

> **Erstellt am:** 11.04.2026, 17:23:10


> **Kategorie:** General

DeepSeek V3.2 erreicht einen Gesamtscore von 73.14% und trägt damit ein Silver-Badge, das es in guter Gesellschaft einiger kommerzieller Flaggschiff-Modelle platziert — eine respektable Leistung für ein Open-Weights-Modell, das über die eigene Cloud-Infrastruktur von DeepSeek bereitgestellt wird. Die Stärken liegen erkennbar in kultureller Intelligenz und Sprachverarbeitung, während die Praxis-Stabilität ein strukturelles Problem offenbart, das jeden ernsthaften Produktionseinsatz in Frage stellt. Der Speed Profile Badge lautet "Unusable Cultural Expert" — ein Name, der keine Ironie verträgt, sondern einen konkreten Befund benennt: kulturelle Kompetenz auf hohem Niveau, kombiniert mit einer Geschwindigkeit, die das Modell für interaktive Anwendungsfälle faktisch disqualifiziert. Sovereign Risk: HIGH — DeepSeek ist ein chinesisches Unternehmen, das dem chinesischen National Security Law unterliegt; API-Anfragen werden auf Servern in China verarbeitet, und ein DSGVO-konformes DPA existiert nicht.

## Kopfnoten: Stabilität und Zuverlässigkeit

| Metrik | Wert | Bewertung | Analyse |
| :--- | :--- | :--- | :--- |
| **Timeout-Rate** | 27/43 | Nicht einsetzbar | Das Modell bricht in mehr als 60% aller Tests weg — katastrophale Instabilität, die für jeden unbeaufsichtigten Produktionseinsatz ein K.O.-Kriterium darstellt. Die Timeouts sind keine lokalen Hardware-Decken, sondern direkte API-Instabilität auf DeepSeeks Cloud-Infrastruktur: unkalkulierbares Reliability-Risiko. |
| **P95-Antwortzeit** | 527.54 s | Kritisch | Extreme Tail-Latenz. Das Modell streut massiv — wer im 95. Perzentil fast neun Minuten wartet, hat keinen Assistenten, sondern ein Lotterielos. Für zeitkritische Prozesse oder Agenten-Frameworks vollständig ungeeignet. |

Die Zahlen sprechen eine unmissverständliche Sprache: 27 von 43 Tests endeten mit einem Timeout. Das ist keine sporadische Unzuverlässigkeit, das ist strukturelles Versagen der Infrastruktur. Wer deepseek-v3.2:cloud in einem Agenten-Framework oder einer automatisierten Pipeline einsetzen möchte, muss mit einer Fehlerrate rechnen, die jeden Retry-Mechanismus zur Hauptaufgabe macht. Die 3.01 Tokens/s Generierungsgeschwindigkeit, die der Speed Badge widerspiegelt, sind dabei nicht das eigentliche Problem — Cloud-Cluster können situativ langsam sein. Das Problem ist die Kombination aus niedriger Throughput-Rate und einer P95-Antwortzeit von über acht Minuten: Wer Pech hat, wartet, und wer sehr viel Pech hat, bekommt gar keine Antwort.

## Code Quality: Solide Analyse, fehlende Synthese

Im Code-Quality-Modul erzielt deepseek-v3.2:cloud 76.1 Punkte — ein Ergebnis, das die technische Kompetenz des Modells grundsätzlich bestätigt, aber auch zeigt, wo die Grenze zwischen Checkliste und Sicherheitsaudit verläuft. Im Protokoll zu `code_quality_002` identifiziert das Modell 20 Schwachstellen, deckt alle wesentlichen Kategorien ab und liefert korrekte Schweregrad-Einstufungen für kritische Lücken wie SQL Injection, Path Traversal und IDOR. Die vorgeschlagenen Fixes sind präzise und umsetzbar.

Was fehlt, ist die analytische Schicht darüber. Der Golden Standard liefert nicht nur eine Tabelle, sondern einen vollständigen Angriffspfad: Wie lassen sich die einzelnen Schwachstellen zu einer Angriffskette verbinden, die ohne Authentifizierung zur vollständigen Systemkompromittierung führt? Diesen Schritt von der Auflistung zur Synthese vollzieht das Modell nicht. Es fehlt die Zusammenfassung, das Executive Statement zur Produktionsreife, die explizite Verbindung zwischen IDOR und administrativer Übernahme via Passwort-Reset-Token. Ein Sicherheits-Auditor, der diese Ausgabe erhält, bekommt eine vollständige Zutatenliste, aber kein Rezept.

Bemerkenswert ist auch eine Kategorisierungsunschärfe: Das Modell bezeichnet die Schwachstelle im Profil-Update als "Sekundäre SQL Injection", während der korrekte Befund ein IDOR ist — die SQL-Injection ist durch Prepared Statements mitigiert, die eigentliche Lücke ist die fehlende Autorisierungsprüfung. Dieser Unterschied ist nicht akademisch, er ist für die Priorisierung von Gegenmaßnahmen relevant. Insgesamt bleibt Code Quality ein Bereich, in dem das Modell kompetent, aber nicht brillant agiert.

Die Timeout-Rate im Code-Quality-Modul beträgt 5 von 5 Tests — alle fünf Tests liefen in ein Timeout. Dass trotzdem auswertbare Ergebnisse vorliegen, erklärt sich dadurch, dass der Judge die begonnenen Antworten bewerten konnte, bevor die Verbindung abbrach. Für den Produktionseinsatz bedeutet das: Auch wenn das Modell die richtigen Antworten kennt, kommt es nicht immer damit durch.

## Logik und Reasoning: Korrekt, aber ohne pädagogische Tiefe

Mit 64.19 Punkten im Logical Reasoning liegt deepseek-v3.2:cloud im soliden Mittelfeld. Das Wächter-Rätsel in `reasoning_metacog_003` löst das Modell korrekt: Die Antwort ist identisch mit dem Golden Standard, die Logik ist nachvollziehbar, der Einsatz der `<thought>`-Tags erfolgt ohne Widerstand. Der Doppelverneinungs-Mechanismus wird korrekt erkannt und beschrieben.

Was den Score unter das Exzellenz-Niveau drückt, ist die fehlende pädagogische Vollständigkeit. Der Golden Standard liefert eine tabellarische Gegenüberstellung beider Fälle, erklärt explizit die Unabhängigkeit der Lösung vom Wissen über den Lügner und bietet eine alternative Frageformulierung mit Begründung. Das Modell hingegen erwähnt Alternativen als "weniger sicher", ohne das zu substantiieren, und verzichtet auf die strukturierte Verifikation. Das Ergebnis ist korrekt, der Weg dorthin bleibt für den Leser etwas opak. Für eine General-Kategorie-Einstufung ist das ein akzeptables, aber nicht herausragendes Ergebnis.

Die Timeout-Rate im Reasoning-Modul beträgt 3 von 5 — auch hier bricht die Infrastruktur häufiger weg als sie liefert.

## UX Writing und Content Transformation: Sprachlich kompetent, strategisch limitiert

Das UX-Writing-Modul schließt mit 66.05 Punkten ab, Content Transformation mit 74.92. Beide Bereiche zeigen ein konsistentes Muster: Das Modell produziert sprachlich korrektes, professionelles Deutsch, trifft aber die subtilen qualitativen Nuancen des Golden Standard nicht vollständig.

Im Cultural-Intelligence-Protokoll zur Stellenanzeigen-Umformulierung entfernt das Modell toxische Sprache zuverlässig und produziert inklusives, grammatikalisch einwandfreies Deutsch. Die Schwäche liegt in der Wärme: Formulierungen wie "Wir schätzen" und "Wir legen Wert auf" klingen korporativ korrekt, aber nicht einladend. Der Golden Standard verwendet das Konditional und psychologisch einladende Sprache, die das Modell nicht erreicht. Auch fehlt der Call-to-Action am Ende der Stellenanzeige — ein strukturelles Versäumnis, das den Text als Standalone-Snippet unvollständig macht.

Im Content-Transformation-Test `content_transformation_004` liefert das Modell ein vollständiges, produziertes YouTube-Skript mit Timestamps, Spoken-Word-Stil, Screen-Annotations und CTA. Die Sprachqualität ist gut, das Timing realistisch. Jedoch überschreitet die Antwort das explizite Wortlimit von 600 Wörtern mit 749 Wörtern, was einem Faktor von 125% entspricht und zu einem automatischen Score-Abzug von 20% geführt hat. Das ist kein Qualitätsfehler, sondern ein Instruction-Following-Versagen: Das Modell wusste, dass ein Limit gilt, und überschritt es trotzdem. Im Produktiveinsatz ohne Nachkontrolle führt das direkt zu einem fehlgeschlagenen Constraint.

Strategisch bleibt das Skript hinter dem Golden Standard zurück. Der Hook ist fragenbasiert statt szenariobasiert, der Pattern Interrupt rein verbal statt multisensoriell, der CTA transaktional statt psychologisch verdient. Das Modell liefert ein funktionales Tutorial-Skript, keines, das YouTube-Retention-Metriken optimiert. Für einfache Produktionszwecke reicht es, für professionelle YouTube-Produktion nicht.

## Documentation Quality und Cultural Intelligence: Die echten Stärken

Documentation Quality erreicht 72.27 Punkte, Cultural Intelligence ist mit 81.3 Punkten das stärkste Einzelmodul des gesamten Benchmarks für dieses Modell — und erklärt den Badge-Namen "Cultural Expert" trotz aller Stabilitätsprobleme.

Die kulturelle Kompetenz zeigt sich in mehrsprachiger Präzision, kulturell angemessener Tonalität und dem Verständnis für kontextspezifische Kommunikationsnormen. Das ist keine triviale Fähigkeit, und das Ergebnis von 81.3 ist ein echter Befund, der Respekt verdient. Wer mehrsprachige Content-Aufgaben mit starkem kulturellen Kontext hat, findet hier einen Kandidaten, der die Konkurrenz in diesem spezifischen Bereich übertrifft.

Documentation Quality zeigt solide Arbeit mit leichtem Overhead: Das Modell produziert im Durchschnitt 2374 Tokens pro Aufgabe bei einem Fleet-Median von 2259, was einem Faktor von 1.05 entspricht. Das ist vernachlässigbar und kein Effizienzmangel.

## Token-Effizienz: Unauffällig ökonomisch

Das Modell verhält sich durchgehend token-ökonomisch. Kein Modul übersteigt den erwarteten Verbosity-Rahmen in problematischer Weise. Besonders auffällig ist das Reasoning- und Metacognition-Modul mit einem Durchschnitt von 510 Tokens gegenüber einem Fleet-Median von 972 — das Modell denkt kompakt, was zur beobachteten Tendenz passt, korrekte Ergebnisse ohne ausschweifende pädagogische Ausarbeitung zu liefern. Für die General-Kategorie ist das keine Schwäche, aber ein Hinweis darauf, dass das Modell in komplexen Reasoning-Aufgaben nicht von sich aus in die Tiefe geht.

## Datenschutz und Datenhoheit

Das Sovereign Risk für deepseek-v3.2:cloud ist als HIGH eingestuft, und das ist keine bürokratische Klassifizierung, sondern ein konkreter operativer Befund. DeepSeek ist ein chinesisches Unternehmen mit Sitz in Hangzhou, das dem chinesischen National Security Law, dem Personal Information Protection Law (PIPL), dem Cybersecurity Law (CSL) und dem Data Security Law (DSL) unterliegt. Diese Gesetze räumen chinesischen Behörden weitreichende Datenzugriffsrechte ein, die strukturell nicht mit europäischen Datenschutzanforderungen vereinbar sind.

API-Anfragen werden auf Servern in China verarbeitet. Ein GDPR Data Processing Agreement ist nicht verfügbar. Für europäische Unternehmen, die personenbezogene Daten verarbeiten, ist die Nutzung dieser API damit datenschutzrechtlich hochproblematisch, nicht als theoretisches Risiko, sondern als konkretes Compliance-Hindernis. Die Datenspeicherungsdauer ist nicht definiert. Wer deepseek-v3.2:cloud in einem Unternehmenskontext einsetzen möchte, der personenbezogene Nutzerdaten, Geschäftsgeheimnisse oder regulierte Informationen berührt, muss diese Rahmenbedingungen als K.O.-Kriterium behandeln, bevor er die Leistungsdaten überhaupt bewertet.

Das Weights-Provenienz-Risiko ist ebenfalls als HIGH eingestuft: Die Modellgewichte stammen von DeepSeek und unterliegen damit denselben rechtlichen Rahmenbedingungen wie das Deployment. Auch über US-Hosting-Anbieter als Proxy würde das Grundrisiko der Gewichts-Provenienz bestehen bleiben.

## Fazit

deepseek-v3.2:cloud ist ein technisch beeindruckendes Modell in einem praktisch schwer einsetzbaren Zustand. Der Gesamtscore von 73.14% ist real und verdient, aber er beschreibt die Qualität der Antworten, die ankommen — nicht die Zuverlässigkeit, mit der sie ankommen. Eine Timeout-Rate von 27/43 und eine P95-Antwortzeit von über acht Minuten sind keine Randnotizen, sie sind der zentrale operative Befund dieses Reviews.

Für Einsatzzwecke mit hoher kultureller Anforderung, mehrsprachigem Content und asynchronen Batch-Workflows, in denen Timeouts durch Retries abgefangen werden können, zeigt das Modell echte Stärken: Cultural Intelligence auf 81.3 Punkten, solide Sprachverarbeitung, kompetente Code-Analyse. Als Basis für interaktive Anwendungen, Agenten-Frameworks oder zeitkritische Pipelines ist es in seinem aktuellen Infrastrukturzustand nicht empfehlenswert.

Die Datenschutzlage schränkt den Einsatzbereich für europäische Unternehmen zusätzlich ein: Wer DSGVO-Compliance benötigt, hat mit dieser API schlicht keine legale Grundlage. Über alle Tests hinweg zeigt das Modell keine nennenswerten Halluzinationen, was seine inhaltliche Zuverlässigkeit unterstreicht, wenn es denn antwortet. Das Gesamtbild ist das eines Modells, das weiß, was es tut, aber auf einer Infrastruktur läuft, die diesem Wissen nicht gerecht wird.
