## Code Quality: Sicherheitsanalyse mit Haltung

Der Code-Quality-Score von 84,24 Punkten ist das stärkste Einzelergebnis dieses Modells — und er ist verdient. Im detaillierten Protokoll zu code_quality_002 zeigt das Modell, was es kann: Es identifiziert alle 19 Schwachstellen in einem absichtlich fehlerhaften PHP-Code-Sample, darunter sämtliche fünf impliziten Expert-Vulnerabilities, die keine explizite Markierung im Code tragen. Mail Header Injection, Second-Order SQL Injection via Cookie, schwache Reset-Token-Generierung mit `rand()` und `md5`, fehlende Cookie-Flags und Username-Enumeration — alles korrekt erkannt, korrekt beschrieben, mit praxistauglichen Fixes versehen.

Die Schweregrad-Einstufungen weichen in vier Fällen vom Golden Standard ab: Path Traversal und Type Juggling werden als "High" statt "Critical" eingestuft, Mail Header Injection und der schwache Reset-Token umgekehrt höher bewertet als der Referenzwert. Das sind keine Fehler, sondern unterschiedliche Risikoeinschätzungen — und die des Modells sind in mindestens zwei Fällen argumentativ vertretbar. Was fehlt, ist eine explizite Proof-of-Concept-Angriffskette, wie sie der Golden Standard demonstriert. Das ist ein echter Unterschied: Wer einem Entwicklerteam erklären muss, warum eine Lücke kritisch ist, braucht die Kette, nicht nur die Klassifikation.

Die Formatierung ist tadellos: 19-zeilige Markdown-Tabelle, konsistente Spaltenstruktur, knappe Erklärungen im Tabellenkörper und ausführliche Detail-Sektionen für die impliziten Vulnerabilities darunter. Der Judge vergibt 5/5 für Task Compliance — das höchste Einzelurteil im gesamten Test.

Der Golden Standard liefert eine Verifikationstabelle, Visualisierungen, fünf explizite Begründungen und eine Diskussion alternativer Formulierungen. Das Modell gibt drei kurze Bullet Points. Die Aufgabe verlangt explizit, "verschiedene Ansätze zu erkunden" — das tut das Modell nicht. Der Judge wertet das als direkte Anforderungsverletzung und landet bei Score 3 statt 4. Das ist methodisch korrekt: Eine richtige Antwort, die den Aufgabenrahmen ignoriert, ist keine vollständige Antwort.

Für ein Modell der General-Kategorie, das explizit auf tiefes Reasoning ausgelegt ist, ist das eine vermeidbare Schwäche. Nicht ein Denkfehler, sondern ein Instruktionsfehler — und das ist, wenn überhaupt, das Enttäuschendere von beiden.

## Datenschutz und Datenhoheit

Anthropic ist ein US-amerikanisches Unternehmen mit Sitz in San Francisco, und das hat rechtliche Konsequenzen, die man kennen sollte. Das berechnete Sovereign Risk liegt bei MEDIUM: Anthropic unterliegt dem CLOUD Act, was bedeutet, dass US-Behörden unter bestimmten Voraussetzungen Zugriff auf verarbeitete Daten verlangen können — auch dann, wenn die Daten physisch in Europa lägen. Tatsächlich werden die Daten ausschließlich in den USA verarbeitet, was diesen Punkt noch direkter macht.

Für europäische Unternehmen gibt es eine teilweise Absicherung: Anthropic stellt ein GDPR-konformes Data Processing Agreement (DPA) bereit, und Standardvertragsklauseln (SCCs) sind verfügbar. Die Datenspeicherung ist auf 30 Tage begrenzt. Das DPA löst das CLOUD-Act-Problem nicht, reduziert aber das Compliance-Risiko für Unternehmen, die DSGVO-konform operieren müssen. Wer hochsensible Daten verarbeitet — Gesundheitsdaten, Finanzdaten, personenbezogene Informationen im Sinne der DSGVO — sollte die Nutzung mit der eigenen Rechtsabteilung abstimmen. Für die meisten technischen Anwendungsfälle ohne besonders schützenswerte Daten ist das Profil handhabbar.
